## 별도 환경 결과

새 임시 D1/Worker에서 166개 검사 중 159개 통과, 7개 실패입니다. 기존 3차 수정 회귀 152개는 모두 통과했고, 새로 추가한 14개 중 7개에서 문제가 발견됐습니다. 실패 7개는 원인 기준 2종류로 묶입니다.

### R4-01. 문서·레스 수정 및 삭제 경로의 대상 ID 누락 — 낮음

로그인 상태에서 다음 요청에 `{ "title":"x", "content":"x", "hidden":true }`를 보냅니다.

- `PATCH /api/entries`
- `DELETE /api/entries`
- `PATCH /api/entries/practice/comments`
- `DELETE /api/entries/practice/comments`

실제 응답은 503입니다. 없는 대상 ID를 D1 조회 바인딩에 전달하기 전에 검사하지 않는 것이 원인입니다. 잘못된 요청으로 400 또는 대상 없는 경로로 404/405를 반환해야 합니다. 앞서 수정한 카테고리 경로 검사와 같은 검사가 문서·레스 경로에도 필요합니다. 다른 사람의 데이터 수정·삭제 성공을 의미하지는 않습니다.

### R4-02. 비밀번호 객체의 문자열 변환에서 서버 예외 — 중간

비밀번호 값으로 `{ "toString":null, "valueOf":null }`을 보내면 아래 경로에서 503이 발생합니다.

- 기존 아이디를 지정한 `POST /api/login`
- 일반 회원의 `DELETE /api/me`
- 비밀글의 `POST /api/entries/:id/unlock`

입력 자료형 검사 없이 `String(b.password || '')`로 강제 변환해 예외가 발생합니다. 가입과 비밀글 생성은 문자열 검증을 하지만, 실제 인증을 처리하는 세 경로는 별도의 검증이 필요합니다. 자료형과 길이를 먼저 확인하고 400/401로 거부해야 합니다. 잘못된 탈퇴 시도 후 계정이 유지되는 것을 확인했습니다. 인증 우회·계정 탈취로 확인된 문제는 아닙니다.
