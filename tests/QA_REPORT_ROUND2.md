# RP LAND 2차 검증: 버그 수정과 악의적 시나리오 점검

검증 일자: 2026-09-28
검증 기준 코드: GitHub `main` 커밋 `b2c159a` + 이 문서와 함께 반영한 수정
결과 요약: 실제 오류 5건을 재현·수정했고, 수정 후 저장소 회귀 285건, 계정 구성 시나리오 167건, 악의적 시나리오 56건이 모두 통과했습니다.

## 1. 환경과 계정

운영 사이트와 무관한 로컬 Cloudflare Worker(wrangler dev)와 매번 새로 만든 임시 D1 데이터베이스에서 실행했습니다. 운영 데이터는 건드리지 않았습니다.

|역할|계정 수|비고|
|---|---:|---|
|총관리자|1|테스트 전용 설정 키로 지정|
|부관리자|2|총관리자의 임명 API로 임명|
|일반회원|4|작성자, 공동 편집자, 제3자, 자진 탈퇴 대상|
|비로그인 방문자|-|공개 조회와 접근 거부 확인|

7개 계정이 동시에 활성화된 상태(총관리자 1, 부관리자 2, 일반회원 4)를 API로 직접 확인한 뒤 기능을 시험했습니다.

## 2. 발견하고 수정한 오류

다섯 건 모두 수정 전에 실제 요청으로 재현했고, 수정 후 같은 요청이 의도대로 거부되는 것을 확인했습니다. 수정은 `app/api/[...path]/route.ts`의 5개 줄에 들어 있습니다.

|번호|증상|수정 전 응답|수정 후 응답|
|---:|---|---|---|
|1|존재하지 않는(또는 이미 탈퇴한) 회원 ID로 역할 변경·강제 탈퇴|200 성공, 감사 기록에 실체 없는 대상이 남음|404 대상을 찾을 수 없음, 기록 없음|
|2|카테고리 이름 중복 생성·변경|503 "일시적으로 처리할 수 없습니다"|409 이미 사용 중인 카테고리 이름|
|3|카테고리 배열에 객체나 중첩 배열을 넣어 스레드 생성|503|400 잘못된 카테고리|
|4|편집 권한 공유·회수 API의 `userId`에 객체나 배열|503|400 회원을 찾을 수 없음|
|5|로그인 전에도 닿는 엔드포인트(예: 회원가입)에 JSON 리터럴 `null` 전송|503|400 (필드 검증 실패로 정상 처리)|

원인은 두 갈래입니다. 1번은 UPDATE 실행 결과(`meta.changes`)를 확인하지 않고 항상 성공을 반환한 것입니다. 스레드 삭제 등 같은 파일의 다른 곳에는 이미 있는 확인이 이 두 곳에만 빠져 있었습니다. 2~5번은 요청 값의 타입을 확인하지 않고 DB 바인딩에 넘겨서, 예측 가능한 입력 오류가 서버 예외로 번지고 최상위 예외 처리에서 "서버 장애"처럼 보이는 503이 된 경우입니다. 회원가입의 중복 아이디 처리(409)처럼 이미 잘 처리한 곳과 같은 방식으로 맞췄습니다.

세부 변경은 다음과 같습니다.

- 강제 탈퇴는 `active=1` 조건을 추가해 이미 탈퇴한 회원에게 반복 호출해도 404가 되게 했습니다. 동시에 두 번 호출하면 하나는 성공, 하나는 404로 일관되게 처리됩니다.
- 카테고리 PATCH에는 존재 확인(404)을 새로 넣었습니다. 이름 검증(`str`)은 try 블록 밖에 두어, 길이 오류가 중복 오류로 잘못 바뀌지 않게 했습니다.
- 요청 본문이 `null`이거나 객체가 아니면 빈 객체로 취급합니다. 배열 본문은 기존에도 안전하게 검증 실패로 처리되고 있어 그대로 두었습니다.

## 3. 악의적 시나리오에서 방어가 확인된 항목

공격자 관점으로 56개 점검을 만들어 실행했고, 위 3~5번을 제외한 모든 항목은 수정 전에도 방어되고 있었습니다.

- 인증: 위조 세션 쿠키 거부, 비로그인 관리자 API 401, 일반회원의 임명 시도 403.
- 권한 상승: 회원가입·댓글 본문에 `role`, `author_id`를 끼워 넣어도 무시. 총관리자가 자기 ID를 대문자로 바꿔 자기 보호를 우회하려는 시도도 안전하게 차단(총관리자 권한 유지 확인).
- SQL 인젝션: 스레드 본문·카테고리 이름·검색 필터에 인젝션 문자열을 넣어도 저장된 값은 원문 그대로이고, users 테이블과 회원 역할은 변하지 않음.
- 비밀글: 한 글의 열람 토큰을 다른 글의 쿠키 이름으로 재사용해도 잠김 유지. 총관리자도 비밀번호 없이는 열람 불가. 작성자·관리자가 아닌 회원은 편집자 목록 조회 불가.
- 무차별 대입: 특정 계정 로그인, 비밀글 비밀번호 모두 20회 근처에서 429 차단.
- 위험한 관리 기능: 전체 초기화 엔드포인트는 인증 헤더 없음, 잘못된 토큰, 올바른 토큰이지만 확인 문구 오류 세 경우 모두 403이고 데이터 유지.
- 서버 크래시 유도: 4만 단계 중첩 JSON, JSON 배열 본문, `__proto__`·`constructor` 키 삽입에도 서버가 정상 응답하고 전역 객체 오염 없음.
- 주사위 남용: 음수·0개·1억 초과 범위 거부.

## 4. 남은 위험과 개선 제안

오류로 분류하지는 않았지만 운영 전에 판단할 만한 항목입니다. 이 중 어느 것도 이번에 코드를 바꾸지 않았습니다.

1. **대량 가입**: 가입 제한이 "시도한 아이디"별로만 걸려서, 서로 다른 아이디로 계속 가입하는 것은 애플리케이션 단에서 막히지 않습니다(15개 연속 가입 성공을 확인). 기획안에도 적힌 한계입니다. Cloudflare 쪽 보호가 얼마나 완화해 주는지는 로컬에서 확인할 수 없었습니다.
2. **캐릭터명 문자 제한 없음**: 아이디는 허용 문자가 정해져 있지만 캐릭터명은 길이만 검사합니다. 방향 제어 문자(RTL override)나 보이지 않는 문자가 그대로 저장됩니다. 장식 문자를 쓰는 RP 문화를 고려해, 전부 막기보다 방향 제어·제로폭 문자만 걸러내는 방식이 적당해 보입니다.
3. **아이디 대소문자 구분**: `user1`과 `User1`이 서로 다른 계정으로 가입됩니다. 사칭이 걱정되면 소문자 기준 중복 검사를 고려할 수 있습니다.
4. **비밀번호 해시 강도**: PBKDF2(SHA-256, 반복 100,000회)입니다. 지금 규모에서 즉시 문제라고 보지는 않지만, 반복 횟수를 올리거나 다른 방식으로 옮기는 것을 나중에 검토할 만합니다.
5. **추적성**: 기획안에 적힌 배포 코드 해시(`34c6e2a…`)와 검증 자료 추가 커밋(`987aeed…`)은 공개 저장소에서 조회되지 않습니다. 배포 때 태그를 남기면 대조가 쉬워집니다.

## 5. 테스트 환경의 간헐적 실패

로컬 개발 서버에서 요청 한 건이 503 또는 "Worker restarted mid-request"로 실패하는 현상을 이번 작업 중 세 번 봤습니다. 세 번 모두 다른 테스트 항목이었고(비-JSON 쓰기 거부, 손상된 JSON 거부 두 번) 같은 스위트를 다시 실행하면 통과했으며, 수정한 코드와 무관한 요청 검증 경로였습니다. 원인은 찾지 못했습니다. 로컬 개발 서버의 특성일 가능성이 높다고 보지만 확정은 아닙니다. 그래서 위 통과 수치는 "일시적 실패 후 재실행 통과"를 포함한 결과입니다. 운영 환경에서 같은 현상이 나는지는 확인하지 못했습니다.

## 6. 검증 범위와 한계

- 실제 브라우저에서 화면 버튼을 클릭한 검사는 하지 못했습니다(헤드리스 브라우저를 설치할 수 없는 환경). WebMCP 검색 도구도 검증하지 못했습니다.
- 1,500개 레스 한도의 동시 등록 검증은 이번에 새로 만들지 않았고, 저장소 기존 스위트의 결과에 의존합니다.
- 운영 환경(Cloudflare 네트워크, 실제 트래픽, 장시간 부하)에서의 동작은 확인하지 않았습니다.
- 통과는 "시도한 입력에서 문제가 없었다"는 뜻이며 모든 입력 조합의 안전을 보장하지 않습니다.

## 7. 재실행

빌드 후 실행합니다. 각 스크립트는 자체적으로 임시 DB와 서버를 만들고 끝나면 종료합니다.

```sh
pnpm run build
node tests/run-local.mjs        # 기존 통합 검증 247건
node tests/run-render.mjs       # 서식·주사위 검증 38건
node tests/qa-full-run.mjs      # 1·2·4 계정 구성 시나리오 167건 (포트 8801)
node tests/qa-adversarial.mjs   # 악의적 시나리오 56건 (포트 8802)
```

`qa-full-run.mjs`와 `qa-adversarial.mjs`는 실패해도 중단하지 않고 끝에 전체 결과를 출력합니다.

## 8. 사이트 반영 전 재검증 (2026-09-28)

첨부 패치를 기존 Sites 소스에 적용한 뒤 빌드하고, 새 격리 DB에서 네 스위트를 다시 실행했습니다. 기존 HTTP 247건, 서식·주사위 38건, 계정 구성 167건, 악의적 입력 56건으로 총 508건이 통과했습니다. 이번 재실행에서는 실패나 재시도가 없었습니다. 운영 데이터는 변경하지 않았으며 화면 변경이 없는 서버 패치이므로 추가 브라우저 검사는 수행하지 않았습니다.

추가한 두 QA 스크립트는 실패 항목이 있으면 종료 코드 1을 반환하도록 보완했습니다. 위 4절의 개선 제안은 이번 패치에 포함하지 않았습니다.
