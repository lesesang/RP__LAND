## 새로 확인한 문제

실패 검증의 수와 독립적인 문제의 수는 다릅니다. 별도 환경에서 116개 검증 중 107개 통과, 9개 실패였으며 원인 기준으로 6종류입니다. 검증 실패가 모두 권한 탈취 취약점을 의미하지는 않습니다.

### R3-01. 가입과 로그인에서 비밀번호 공백 처리 불일치 — 우선 수정

- 재현: 임시 계정을 비밀번호 `  Space-Password!1  `로 가입하면 200. 동일한 문자열로 로그인하면 401. 공백을 제거한 `Space-Password!1`로 로그인하면 200.
- 원인: 공통 `str()`이 가입 시 비밀번호 앞뒤 공백을 제거하지만 로그인과 탈퇴 검증은 입력 그대로 비교합니다. 비밀글 비밀번호에도 같은 공통 함수가 사용됩니다.
- 영향: 사용자가 가입 때 입력한 비밀번호로 로그인하지 못하며, 의도와 다른 문자열이 실제 인증값이 됩니다. 다른 사람의 비밀번호를 알아내거나 계정을 탈취한 결과는 아닙니다.
- 권장: 비밀번호는 원문을 보존하고 허용 길이를 별도로 검사합니다. 기존 공백 제거 계정과의 전환 정책을 결정해야 하며 로그인에서 무조건 trim하는 방식은 피합니다.
- 증거 범위: 격리된 로컬 Worker/D1에서 재현. 운영 계정을 정확히 8개로 유지하기 위해 운영에 추가 가입하지 않았습니다.

### R3-02. 비정상 페이지 번호가 서버 오류로 전파 — 중간

- 재현: 비로그인 `GET /api/entries?page=Infinity`, `GET /api/schedule?page=Infinity`, `GET /api/schedule?page=1e100`.
- 실제: 로컬에서는 503. 정상 페이지로 보정하거나 400을 반환해야 할 입력 오류입니다.
- 원인: 유한 정수와 안전한 OFFSET 범위를 확인하지 않은 채 D1에 전달합니다. 스레드 목록과 시간표가 서로 다른 페이지 정규화 코드를 사용합니다.
- 영향: 잘못된 URL 한 건의 처리가 실패합니다. 전체 서비스 중단이나 지속적인 자원 고갈은 입증하지 않았습니다.
- 권장: 두 API에 동일한 유한 양의 정수 검사와 페이지 상한을 적용합니다.

### R3-03. 카테고리 변경에서 대상 ID 누락 검사 없음 — 낮음

- 재현: 관리자 권한으로 `PATCH /api/categories`, 본문 `{"name":"missingpath"}`.
- 실제: 로컬 503. 400/404/405처럼 잘못된 경로임을 나타내야 합니다.
- 원인: 없는 `p[1]` 값을 D1 바인딩에 넘깁니다.
- 권장: PATCH 처리 전 경로 ID 유무를 확인합니다. 일반 회원의 관리자 권한 우회는 아닙니다.

### R3-04. 예약 시각의 자료형 확인 전에 Date 변환 — 중간

- 재현: 로그인한 사용자가 글 생성 시 `scheduledAt: {"toString":null,"valueOf":null}` 전송.
- 실제: 로컬 503. 잘못된 입력으로 400을 반환해야 합니다.
- 원인: `new Date(scheduled)` 호출 후에 문자열 여부를 검사하여, 객체의 원시값 변환에서 예외가 먼저 발생합니다.
- 권장: 문자열과 길이부터 검사한 뒤 날짜를 변환합니다. 글 수정에서도 같은 함수를 사용하므로 함께 회귀 검증합니다.

### R3-05. 시간표 공개 옵션의 잘못된 자료형을 허용 — 중간

- 재현: 미래 예약에 `scheduleMeta: {"title":{},"author":[],"categories":1}` 전송.
- 실제: 로컬 200으로 생성. 코드가 literal `false`만 비공개로 취급하여 이 값들을 공개로 해석합니다.
- 영향: 잘못된 API 요청의 공개 설정이 조용히 바뀝니다. 정상 UI에서 이런 요청이 발생하는지는 이번에 확인하지 않았습니다.
- 권장: 선택적 필드는 생략 시 기본값을 쓰고, 존재하면 반드시 boolean인지 확인합니다. `scheduleListed`, `previewOpen`도 같은 정책으로 정리합니다.

### R3-06. 문자열 false가 비밀글 활성화로 해석 — 낮음

- 재현: 글 생성 요청에 `isSecret: "false"`와 유효한 비밀글 비밀번호를 전송.
- 실제: 로컬 200으로 비밀글 생성. 문자열 false는 JavaScript에서 참으로 취급됩니다.
- 영향: 잘못된 타입의 입력이 거부되지 않고 작성 의도와 다른 공개 상태로 저장됩니다. 비밀글을 공개해 버리는 재현은 아닙니다.
- 권장: `isSecret`은 boolean만 허용하고, 생략 시 false를 기본값으로 사용합니다.

## 실행 방법과 한계

로컬 재현 스크립트는 빌드된 Worker를 사용하고 매 실행 새 임시 D1을 만듭니다. 운영 데이터와 분리됩니다.

```sh
pnpm run build
node tests/qa-round3-fuzz.mjs
```

현재 코드에서는 위 문제들 때문에 종료 코드 1이 예상됩니다. 스크립트는 기존 악의적 시나리오 75개와 이번 추가 41개를 합친 116개 검증이며, 기존 75개를 별도 통과 수로 다시 합산하지 않았습니다.
