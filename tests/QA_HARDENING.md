# RP LAND 추가 개선 (2026-09-28)

## 동작 변경

- 신규 아이디는 ASCII 영문 대소문자를 구분하지 않고 중복 검사한다. 단일 조건부 INSERT로 동시 가입에서도 중복을 막는다. 기존 계정의 아이디, 권한, 글은 변경하지 않는다.
- 로그인은 정확한 표기를 우선한다. 정확히 일치하는 계정이 없고 대소문자 무시 검색 결과가 한 개일 때만 대체 로그인을 허용한다. 과거에 대소문자만 다른 두 계정이 있으면 원래 표기로 로그인해야 한다. 로그인 시도 제한도 소문자 기준으로 공유한다.
- 가입 시도는 동일 Sites 방문자당 15분 동안 10회, 사이트 전체 60회로 제한한다. 플랫폼 방문자 식별 정보가 없는 요청은 하나의 공용 10회 제한을 공유한다. 임의의 전달 IP 헤더나 브라우저 쿠키로 제한 대상을 선택하지 않는다. 성공·실패한 유효 가입 시도를 함께 센다. 대규모 공개 서비스에서는 공용 제한 수치를 재검토해야 한다.
- 제한 카운터를 갱신한 같은 SQL 문에서 값을 반환한다. 429 응답에는 Retry-After를 붙인다. 만료된 카운터는 가입 과정에서 정리한다. 방문자 식별자는 해시로 저장한다.
- 새 레스의 캐릭터명에 제어 문자, 방향 제어 문자, 숨은 공백 등을 거부한다. 일반 장식·한글·결합 이모지는 유지하며, 눈에 보이는 문자가 없는 이름은 거부한다. 기존 게시물은 변조하지 않는다.
- 문서 수정에서도 객체·배열 카테고리 항목을 거부한다. 카테고리·가입의 중복 오류만 409로 처리하고 실제 DB 장애를 중복 이름으로 오인하지 않게 한다.
- 사용법 페이지에 계정·캐릭터명 규칙을 추가한다.

## 비밀번호 저장 방식

기존 PBKDF2-SHA256 100,000회와 사용자별 무작위 salt를 유지한다. Workers의 PBKDF2 상한 문제 때문에 반복 수만 올리는 변경은 하지 않는다. 자체 제작 암호 알고리즘을 추가하지 않는다. 더 강한 KDF 전환은 런타임 지원·부하·기존 해시의 단계적 전환을 함께 검증해야 하는 후속 작업이다.

근거: https://github.com/cloudflare/workerd/issues/1346

## 검증

기존 HTTP, 서식·주사위, 계정 구성 검증과 확장된 악의적 입력 검증을 격리된 DB에서 실행한다. 추가 시나리오는 대소문자 동시 가입, 기존 대소문자 충돌 계정 보존, 로그인 제한 우회 방지, 가입 제한, 문자 검사, 잘못된 문서 수정 후 원문 보존을 포함한다. 브라우저 전수 검사나 분산 공격·실서비스 부하 검증은 아니다.

최종 결과: HTTP 247건, 서식·주사위 38건, 계정 구성 167건, 확장 악의적 입력 75건으로 총 527건 통과. 최종 문자 검사 보완 후 악의적 입력 75건을 다시 통과했다. 빌드 성공. 운영 계정과 게시글은 수정하지 않았다.
